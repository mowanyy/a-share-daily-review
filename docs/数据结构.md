# 数据结构 — 核心数据对象定义

> 目的：把东财原始字段与业务概念隔离。**代码实现时以此为数据模型契约**，东财字段变更只改映射层。
> 版本：v0.5（草稿，随采集层实现迭代）

---

## 1. 涨停股 `LimitUpStock`

当日涨停（含连板）个股，一张表即可支撑「连板梯队」与「炸板」分析。

| 字段 | 类型 | 说明 | 来源 |
|---|---|---|---|
| `trade_date` | str `YYYYMMDD` | 交易日 | 通用 |
| `code` | str | 股票代码（6 位） | 通用 |
| `name` | str | 股票名称 | 通用 |
| `lb_num` | int | 连板数（首板=1） | 涨停池 |
| `first_limit_time` | time | 首次封板时间 | 涨停池 |
| `last_limit_time` | time | 最后一次封板时间 | 涨停池 |
| `open_times` | int | 炸板次数（打开次数） | 涨停池 |
| `seal_amount` | float | 封单金额（万元/亿） | 涨停池 |
| `turnover` | float | 换手率 % | 涨停池 |
| `amount` | float | 成交额 | 涨停池 |
| `industry` | str | 行业 | 涨停池 |
| `concepts` | list[str] | 所属题材/概念 | 概念成分 |
| `is_zt` | bool | 是否最终涨停 | 涨停池/炸板池对照 |

## 2. 炸板股 `BreakStock`

| 字段 | 类型 | 说明 |
|---|---|---|
| `trade_date` | str | 交易日 |
| `code` / `name` | str | 代码 / 名称 |
| `break_times` | int | 炸板次数 |
| `first_seal_time` | time | 首次封板时间 |
| `last_break_time` | time | 最后一次炸板时间 |
| `concepts` | list[str] | 所属题材 |
| `up_pct` | float | 收盘涨幅 %（炸板后回落幅度） |

## 3. 资金流向 `MoneyFlow`

| 字段 | 类型 | 说明 |
|---|---|---|
| `trade_date` | str | 交易日 |
| `code` / `name` | str | 代码 / 名称 |
| `main_net_inflow` | float | 主力净流入（元） |
| `super_net_inflow` | float | 超大单净流入 |
| `big_net_inflow` | float | 大单净流入 |
| `total_inflow` | float | 总流入 |
| `total_outflow` | float | 总流出 |

> 炸板净流入模块 = `炸板股 × 资金流向` 按 `main_net_inflow` 排序。

## 4. 题材 `Theme`

| 字段 | 类型 | 说明 |
|---|---|---|
| `theme_code` | str | 题材/概念代码（东财概念板块） |
| `theme_name` | str | 题材名称 |
| `stage` | str | 运行阶段：`启动 / 发酵 / 高潮 / 退潮` |
| `leader` | str | 龙头（身位最高 / 封板最早） |
| `members` | list[LimitUpStock] | 该题材涨停成员 |
| `member_count` | int | 涨停成员数 |
| `prev_member_count` | int | 昨日涨停成员数（周期判断用） |

## 5. 连板统计 `LadderStats`（指标层产出）

| 字段 | 类型 | 说明 |
|---|---|---|
| `zt_count` | int | 涨停家数 |
| `lianban_count` | int | 连板（≥2 板）家数 |
| `max_lb` | int | 最高连板数（空间板高度） |
| `max_lb_stock` | str | 空间板个股 |
| `break_count` / `break_rate` | int / float | 炸板家数 / 炸板率 |
| `promotion` | dict | 各层级晋级率：`{"1进2": 0.35, "2进3": 0.4, ...}` |

> 情绪温度已独立为「9. EmotionStats」，不挂在 LadderStats 上（由 `analysis/emotion.py` 单独核算）。

## 7. 龙虎榜榜单 `LhbDaily`（v0.4）

| 字段 | 类型 | 说明 | 来源 |
|---|---|---|---|
| `trade_date` / `code` / `name` | str | 交易日 / 代码 / 名称 | 通用 |
| `change_rate` / `turnover_rate` | float | 涨幅 % / 换手率 % | 榜单 |
| `lhb_net_amt` / `lhb_buy_amt` / `lhb_sell_amt` | float | 龙虎榜净买 / 买入前五合计 / 卖出前五合计（元） | 榜单 |
| `reason` | str | 上榜原因（如「连续三日涨幅偏离累计 20%」） | 榜单 |
| `reason_type` | str | 上榜类型说明（如「2家机构买入」「上海资金买入」「普通席位买入」） | 榜单 |
| `buy_seats` / `sell_seats` | int | 买入 / 卖出席位数 | 榜单 |
| `buy_ratio` / `sell_ratio` | float | 买入 / 卖出金额占比 % | 榜单 |

> 一只股票因多个上榜原因会出现多行；`analysis/lhb.py` 按代码去重（取净额绝对值最大一条，原因合并）。

## 8. 龙虎榜席位 `LhbSeat`（v0.4）

| 字段 | 类型 | 说明 | 来源 |
|---|---|---|---|
| `trade_date` / `code` / `name` | str | 交易日 / 代码 / 名称 | 通用 |
| `seat_code` / `seat_name` / `seat_abbr` | str | 营业部代码 / 全名 / 简称 | 席位明细 |
| `act_buy` / `act_sell` | float | 该营业部当日买入 / 卖出金额（元） | 席位明细 |
| `net_amt` | float | 净额（买入 − 卖出，元） | 席位明细 |
| `reason` | str | 上榜原因 | 席位明细 |

> 游资识别：`seat_name + seat_abbr` 拼接后与 `data/hotmoney_seats.py` 的知名游资名单做子串匹配（`tag` 名号 / `style` 风格：打板/趋势/量化/机构/散户）。

## 9. 情绪温度 `EmotionStats`（v0.5，`analysis/emotion.py` 核算）

| 字段 | 类型 | 说明 |
|---|---|---|
| `available` | bool | 是否有足够数据（涨停池为空 → False） |
| `score` | float | 情绪温度 0–100（五维加权合成） |
| `stage` | str | 情绪周期：`冰点期 / 修复期 / 高潮期 / 退潮期`（市场级，带「期」） |
| `stage_reason` | str | 依据句（近 N 日走势 → 今日分数 → 判定） |
| `components` | dict | 今日各维子分 0–100：`zt / height / promote / break / dt` |
| `raw` | dict | 原始输入：`zt_count / max_lb / promote / break_rate / dt_count` |
| `series` | list[dict] | 近 N 日温度序列 `[{date, score}]`（最新在前） |
| `weights_used` | dict | 实际参与加权的权重（缺维时重归一，防 LLM 误读名义权重） |
| `days_used` | int | 计入的天数 |
| `notes` | list[str] | 缺失/降级说明（盘中预览、缺维未计入、序列缺日等） |

> **降级规则**（关键区分）：`*_ok=False` = 数据缺失 → 该维剔除并重归一；`*_ok=True` 但池子为空 = 真实 0 值 → 该维子分取 100（反向维）或 0。
> **维度锚点**（分段线性插值，端点截断）：涨停家数 `{20:0, 70:50, 120:100}`、空间板高度 `{1:0, 4:50, 6:75, 8:100}`、晋级延续率 `{0.0:0, 0.25:50, 0.5:100}`、炸板率(反向) `{0.5:0, 0.30:50, 0.15:100}`、跌停家数(反向) `{50:0, 15:50, 0:100}`。
> **权重**：`zt 0.30 / height 0.20 / promote 0.20 / break 0.15 / dt 0.15`。
> **阶段判定**（方向优先）：R1 冰点期 score<45 且走低 → R2 修复期 score<70 且走高（含低位反弹）→ R3 高潮期 score≥70 且走高 → R4 退潮期 score≥45 且走低 → R5 单日绝对分带（<45 冰点 / 45–69 修复 / ≥70 高潮）。

## 命名与目录约定

- 数据缓存落盘于 `data/`，按 `data/{trade_date}/` 分日存放（JSON/parquet，实现时定）
- 复盘输出落盘于 `output/`，命名 `output/YYYYMMDD_复盘.md`
- 字段一律 snake_case；时间用 `%H:%M`，日期用 `%Y%m%d`
