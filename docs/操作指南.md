# 操作指南（使用手册）

> 面向**日常使用者**的完整操作文档：从环境准备、配置、每天怎么用，到定时推送、盘中监控、Web 工作台、常见问题排查。
> 想看设计细节（需求/数据结构/东财接口/版本管理）见 [docs/](README 文末的「更多文档」表)。
> 本文档随版本更新维护（当前对应 **v0.30.x**）。

## 1. 每天怎么用（三时段总览）

| 时段 | 时间 | 动作 | 产物 |
|---|---|---|---|
| 🕕 盘后复盘 | 交易日 **18:00 后** | `review`（或云端自动推送） | `output/{日期}_复盘.md` 七章报告 |
| 🌙 隔夜预案 | 次日 **9:00 前**（云端 07:30） | `plan` | `output/{日期}_隔夜预案.md` 消息面预案 |
| 🌅 开盘策略 | 竞价后 **9:25-9:30**（本地计划任务准点） | `open` | `output/{日期}_开盘策略.md` 个股清单 |

- 三时段可一键全自动：复盘/隔夜预案走 GitHub Actions 云端推送，开盘策略走本机计划任务（见第 6 节）。
- 只想先用起来：`python -m daily_review web --open` 打开工作台，点按钮即可。

## 2. 环境准备（一次性）

### 2.1 运行环境（固定，勿换解释器）

本项目**固定使用** `E:/conda_envs/envs/mowan_dm/python.exe`（Python 3.14）。不要改用系统 Python 或其他虚拟环境，详见 [docs/开发环境.md](开发环境.md)。

```bash
# 在项目根目录执行（Git Bash 或 cmd 均可）
"E:/conda_envs/envs/mowan_dm/python.exe" -m daily_review <子命令>
# 若用活动 conda 环境且已 pip install -e .，可直接 python -m daily_review <子命令>
```

> 下方命令统一简写为 `python -m daily_review ...`；Windows 下请用上面带路径的完整写法或先激活环境。

### 2.2 安装依赖

```bash
pip install -r requirements.txt
pip install -e .          # 让 daily_review 可导入（只在 mowan_dm 环境内）
```

问答想用向量检索增强再执行 `python -m daily_review qa --setup`；不装自动降级纯关键词，不影响使用。

### 2.3 配置 `.env`（项目根目录，不入库）

```ini
# ── LLM 主后端（必填，想生成 AI 报告需要）──
DEEPSEEK_API_KEY=sk-你的key
LLM_BASE_URL=https://api.deepseek.com        # 当前生产：商汤 SenseNova https://token.sensenova.cn/v1
LLM_MODEL=deepseek-chat                      # 当前生产：deepseek-v4-flash（推理模型）

# ── LLM 兜底后端（可选：主后端 429/5xx/网络失败自动切换）──
DEEPSEEK_FALLBACK_API_KEY=sk-你的兜底key
LLM_FALLBACK_BASE_URL=https://api.deepseek.com
LLM_FALLBACK_MODEL=deepseek-chat

# ── 热点模型（可选：独立模型 B 提炼当日热点，空=回落主模型）──
HOTSPOT_MODEL=

# ── 飞书定时推送（可选，仅 push 命令/GitHub Actions 用）──
FEISHU_WEBHOOK_URL=https://open.feishu.cn/open-apis/bot/v2/hook/xxx
FEISHU_SECRET=你的加签密钥
```

换 LLM 平台只改 `.env` 这几个键，不改代码。缺 key 时 `review --no-llm` / `dashboard --no-llm` 仍可跑通数据+指标+看板。

## 3. 快速开始（5 分钟跑通）

```bash
# 1) 只跑数据+指标（不调 LLM，验证环境/网络）
python -m daily_review review --date 20260806 --no-llm

# 2) 完整复盘（需要 .env 配好 key；有数据可省略 --date 自动探测最近交易日）
python -m daily_review review --date 20260806

# 3) 打开 Web 工作台（推荐日常使用）
python -m daily_review web --open
```

## 4. CLI 命令参考（全）

> 通用：缺省 `--date` 自动探测**最近交易日**；日期格式 `YYYYMMDD`。

### 4.1 复盘三时段

| 命令 | 说明 | 常用参数 |
|---|---|---|
| `review` | 端到端复盘：采集→指标→LLM 七章报告 | `--date 20260806` 指定日（收盘 15:00 后数据完整；龙虎榜 18:00 后完整）、`--no-llm` 只跑数据+指标、`--strategy strategy.user-xxx` 按个人战法驱动次日预案 |
| `plan` | 隔夜预案（**9:00 前**跑）：昨日复盘指标 + 东财 7x24 隔夜消息 → 消息面预案 | `--date 20260812`（预案适用日） |
| `open` | 开盘策略（**9:25-9:30** 跑）：昨日指标 + 今日隔夜预案全文 + 竞价数据 → 个股清单 | `--date 20260812` |

### 4.2 行情与数据

| 命令 | 说明 | 常用参数 |
|---|---|---|
| `kline` | 东财日 K 线 | `--code 600000` 必填、`--lmt 120` 条数、`--klt 101/102/103`（日/周/月）、`--fqt 0/1/2`（不复权/前/后） |
| `realtime` | 新浪实时行情 | `--codes 600601,002398` |
| `calendar` | 权威交易日历（上证日K 实证生成） | `--check 20260818` 判单日、`--year 2026` 列休市日、`--update` 强制联网刷新 |
| `update-data` | 刷新静态缓存 + 重采近 N 天数据（Web「更新数据」按钮同效） | `--date`、`--days 6`、`--force` |

### 4.3 盘中增量监控（v0.27，09:30-15:00 用）

| 命令 | 说明 |
|---|---|
| `intraday baseline` | 早盘采集并保存基准快照（--force 强制刷新） |
| `intraday snapshot` | 拉取当前快照，与基准 diff（新涨停/炸板/回封）落盘（--force-baseline 无基准时自动建） |
| `intraday snapshots` | 列出当日所有增量记录（时间轴累计曲线） |

数据存 `data/intraday/{日期}/`，与收盘缓存（`data/{日期}/`）隔离。

### 4.4 数据看板与问答

| 命令 | 说明 | 常用参数 |
|---|---|---|
| `dashboard` | 近 N 日趋势单文件 HTML + LLM 多日解读 | `--date`、`--days 10`、`--no-llm`、`--open` 自动打开浏览器 |
| `qa` | RAG 知识库问答（13 个数据工具 function-calling） | `--ask "什么是炸板率？"` 一次性提问（缺省进 REPL）、`--no-embedding` 纯关键词、`--top-k 5`、`--rebuild` 强重建、`--setup` 装向量依赖、`--with-reports` 把历史复盘也纳入知识库 |

### 4.5 Web 与启动器

| 命令 | 说明 |
|---|---|
| `web` | Flask 工作台：默认 `--host 127.0.0.1 --port 5000`（**仅本机、无认证，勿暴露局域网**）；`--open` 自动开浏览器 |
| `launch` | tkinter 图形启动器（双击根目录 `启动.bat` 同效）；`--dry-run` 自检不弹窗 |

### 4.6 定时推送（v0.21+）

| 命令 | 说明 |
|---|---|
| `push --type review\|plan\|open` | 生成报告 → 提取标题+摘要 → 飞书推送；周末/休市自动跳过；`--date` 指定、`--force` 强制重推（幂等状态 `data/push_state.json`） |
| `schedule install` | 创建本机计划任务 **周一~周五 09:25 开盘策略准点推送**；`--dry-run` 只打印不创建 |
| `schedule remove` / `list` | 删除/查询计划任务 |

### 4.7 战法与 SKILL 桥（v0.17）

| 命令 | 说明 |
|---|---|
| `skill import <文件.md>` | 把外部 SKILL.md 一键转成个人战法（id=`strategy.user-<sha256>`） |
| `skill export <战法ID> --out 输出.md` | 把战法导出为 SKILL.md（缺 `--out` 打印到控制台） |
| 战法库操作 | Web 战法管理页上传/删除；文件在 `data/strategies/`（不入库） |

## 5. Web 工作台使用说明

启动：`python -m daily_review web --open` → 浏览器打开 `http://127.0.0.1:5000`。

| 页面/面板 | 能做什么 |
|---|---|
| 战法管理 | 上传个人战法（落盘 `data/strategies/`）、导入 SKILL.md 粘贴面板、每行「导出 SKILL.md」下载 |
| 复盘 | 跑复盘（可选战法、`--no-llm`）、跑隔夜预案、跑开盘策略；**历史报告**下拉查看任一日复盘/预案/看板 |
| 问答 | 左侧 RAG 知识库问答；右侧「基金经理分析」面板（4 个风格档案 × 周K/月K）、「多 Agent 会诊」（勾选多 Agent → 综合观点） |
| 数据看板 | 近 N 日趋势图表 + 趋势摘要表 + 情绪温度成分拆解 + LLM 多日解读；「查看该日看板」跳转 |
| 概念池 | 短线题材股票池增删改查（落盘 `data/stock_pool/concepts/*.csv`，自动同步 `knowledge/概念池/*.md` 供问答检索） |

要点：
- 看板加载慢/空白时，后端有进程内缓存 + 文件复用 + 错误兜底，稍等或重新生成即可；「更新数据」按钮可刷新缓存。
- **安全**：无登录鉴权，默认只绑 `127.0.0.1`，不要把 `--host` 改成对外地址。

## 6. 飞书定时推送部署（三档）

### 6.1 云端（复盘 18:00 / 隔夜预案 07:30）—— GitHub Actions

1. 仓库 Settings → Secrets：`DEEPSEEK_API_KEY`、`DEEPSEEK_FALLBACK_API_KEY`、`FEISHU_WEBHOOK_URL`、`FEISHU_SECRET`
2. 三个 workflow 已就绪：`push-review.yml`（复盘 18:00）、`push-plan.yml`（隔夜预案 07:30）、`push-open.yml`（仅手动触发）
3. 手动补发：仓库 Actions 页选中 workflow → `workflow_dispatch`，或本地 `python -m daily_review push --type review --date 20260818 --force`

⚠️ **实测**：GitHub Actions 的 `schedule` 派发会迟到 30-60 分钟甚至漏派（不适合竞价后即时内容），详见 `docs/飞书推送说明.md`。

### 6.2 本机秒级准点（开盘策略 09:25）—— 计划任务

```bash
python -m daily_review schedule install --dry-run   # 先看将执行的命令
python -m daily_review schedule install             # 创建（WEEKLY 周一~周五 09:25）
```

- 日志：`output/scheduled_push_open.log`；双休日连进程都不启动。
- 要求：电脑开机 + 能访问飞书。

### 6.3 推送行为细节

- **幂等**：`data/push_state.json` 记录 (type,date) 已推送，重复触发自动跳过，`--force` 强制重推。
- **跳过/失败也通知**：非 sent 状态会补发 ⏭/❌ 短消息（周末静默、不打扰）；失败后重跑即可。
- **非交易日区分**：报错文案区分「非交易日（交易所休市）」与「交易日但数据未更新」。

## 7. 数据、产物与版本一致性

| 位置 | 内容 |
|---|---|
| `data/{日期}/*.csv` | 每日采集缓存（涨停/炸板/跌停/资金流/龙虎榜/概念板块等） |
| `data/cache/` | 静态缓存：行业映射（7 天 TTL）、概念成分（3 天 TTL）、交易日历 |
| `data/intraday/{日期}/` | 盘中增量监控快照（v0.27） |
| `data/review_snapshots/{日期}.json` | **复盘权威指标快照（v0.30）**：每次完整复盘落盘「昨日情绪温度」等指标，隔夜预案/开盘策略/复盘引用昨日值时**快照优先**，杜绝跨消息数值漂移 |
| `data/stock_pool/` | 概念池与按日切分的选股数据 |
| `data/strategies/` | 用户上传的个人战法 |
| `data/push_state.json` | 推送幂等状态 |
| `output/{日期}_复盘.md` | 七章报告 |
| `output/{日期}_隔夜预案.md` / `_开盘策略.md` | 盘前两份产物 |
| `output/{日期}_看板.html` | 单文件看板 |

- `data/` 与 `output/` 均不入库（gitignore）。
- **情绪温度一致性机制（v0.30）**：预案/复盘提到「昨日情绪温度」时，若昨日已跑过完整复盘（有快照）则**必须逐字引用快照值**（digest 里标 `来源: 昨日复盘快照`）；快照缺失才用重算值并标 `来源: 数据重算`。因此**先跑完整复盘、再跑预案**才能保证前后一致。

## 8. 常见问题（FAQ）

**Q1：LLM 报错 / 报告生成失败？**
- 检查 `.env` 的 `DEEPSEEK_API_KEY` 与 `LLM_BASE_URL`/`LLM_MODEL`。生产后端为推理模型（deepseek-v4-flash），Token Plan 免费额度有调用频率上限（实测 429），主后端限流会自动切兜底重试一次。
- 只想要数据+指标：`review --no-llm` / `dashboard --no-llm`。
- 报「模型把 max_tokens 全用于思考」说明预算被推理占满：把对应调用点 `max_tokens` 调大或换非推理模型。

**Q2：为什么前天消息说情绪温度 74，昨天又变成别的数？**
- 已修复（v0.30）。老版本里「昨日情绪温度」每次生成都重算，代码版本/数据补齐/缺失维度会让同一历史日期算出不同值；现在有复盘权威快照，预案/复盘引用昨日值不再漂移。注意：**先跑完整复盘，再跑预案/开盘策略**，保证快照存在。

**Q3：复盘报告里「龙虎榜」章节显示"未更新"？**
- 龙虎榜 18:00 后更新；在此之前跑 `review` 该章节自动降级为「未更新」。18:00 后重跑即可。

**Q4：提示「数据未更新」 vs 「非交易日」？**
- 用权威交易日历区分：非交易日=休市；交易日但 `zt_count=0`=数据未更新（早于 15:00 或接口异常）。周末/休市 `push` 静默跳过。

**Q5：Web 看板 iframe 空白/不加载？**
- 看板加载有进程内缓存 + 文件复用 + 错误兜底页（HTTP 200 不裸 500）。点「更新数据」或稍后重试；历史日期定稿常新，今日盘中 10 分钟缓存。

**Q6：`push` 没推或者推送迟到了？**
- 先看 `data/push_state.json` 是否已记录（幂等跳过需 `--force`）；云端迟到是 Actions `schedule` 通病，开盘策略改用本机 `schedule install` 秒级准点。核实方法见 `docs/飞书推送说明.md`。

**Q7：网络/接口失败，采集报错？**
- 东财接口有频率限制，采集自带请求间隔+重试（`config.py`：1 秒间隔、3 次重试）。公司网络波动时稍后再试；已有本地缓存时 `review --no-llm` 仍可跑指标。
- 接口结构若被东财改动，采集层会打 `⚠ 字段…已降级为空` 告警并继续（v0.25），不会崩；持续告警请联系维护者查 `docs/东财接口清单.md`。

**Q8：换电脑/换环境怎么复现？**
- 见 `docs/开发环境.md`（解释器、依赖、复现步骤）。

**Q9：周末不想要任何打扰？**
- 已实现：周末/休市 `push` 完全静默，本地计划任务只配周一~周五。
