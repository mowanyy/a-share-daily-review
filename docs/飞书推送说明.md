# 飞书定时推送说明（v0.21.7）

用 **GitHub Actions（免费云端定时）+ 飞书群机器人** 实现每日三份报告自动推送，**电脑关机也能收到**。

## 一、推送时间表

| 报告 | 北京时间 | 触发 cron（UTC） | Workflow 文件 |
|---|---|---|---|
| 复盘报告（盘后） | 18:00 | `0 10 * * 1-5` | `.github/workflows/push-review.yml` |
| 隔夜预案（盘前） | 08:30 | `30 0 * * 1-5` | `.github/workflows/push-plan.yml` |
| 开盘策略（竞价后） | 09:25 | `25 1 * * 1-5` | `.github/workflows/push-open.yml` |

- `1-5` = 周一~周五，自动避开周末
- A 股法定节假日（落在周一~周五时）由程序「数据为空则跳过」兜底，不会发错误推送

## 二、一次性配置步骤

### 1. 飞书群里添加机器人

1. 打开飞书，进入（或新建）一个群
2. 群设置 → 群机器人 → 添加机器人 → **自定义机器人**
3. 给机器人起名（如「每日复盘」）
4. 复制 **Webhook 地址**（形如 `https://open.feishu.cn/open-apis/bot/v2/hook/xxxx`）
5. （可选）设置「签名校验」，会得到一个密钥字符串——填进下方 `FEISHU_SECRET`

### 2. GitHub 配置 Secrets

打开仓库 `https://github.com/mowanyy/a-share-daily-review` →

**Settings → Secrets and variables → Actions → New repository secret**，依次添加：

| Secret 名 | 值 |
|---|---|
| `DEEPSEEK_API_KEY` | 商汤 SenseNova 的 API key（`.env` 里的 `DEEPSEEK_API_KEY`） |
| `DEEPSEEK_FALLBACK_API_KEY` | 官方 DeepSeek 的兜底 key（`.env` 里的 `DEEPSEEK_FALLBACK_API_KEY`） |
| `FEISHU_WEBHOOK_URL` | 飞书机器人 Webhook 地址（`https://open.feishu.cn/open-apis/bot/v2/hook/xxxx`） |
| `FEISHU_SECRET` | 飞书机器人的**签名校验密钥**（机器人设了「签名校验」时必填，否则留空） |

> LLM 的非机密配置（`LLM_BASE_URL` / `LLM_MODEL` / `LLM_FALLBACK_*`）已写死在 workflow 里，无需额外配置。

### 3. 验证推送

1. 代码推送到 GitHub 后，打开仓库 **Actions** 页
2. 左侧选「push-review-report」→ **Run workflow** → 手动触发一次
3. 几秒后飞书群里应收到复盘报告推送
4. 三个 workflow 各手动触发一次验证

## 三、本地手动调试

无需 GitHub，本地直接跑（需先 `pip install` 依赖、`.env` 配好 `FEISHU_WEBHOOK_URL`）：

```bash
"E:/conda_envs/envs/mowan_dm/python.exe" -m daily_review push --type review
"E:/conda_envs/envs/mowan_dm/python.exe" -m daily_review push --type plan --date 20260817
"E:/conda_envs/envs/mowan_dm/python.exe" -m daily_review push --type open --date 20260817
```

推送内容为「标题 + 摘要」（约 500-800 字），完整报告仍落盘 `output/` 供回看。

## 四、已知限制

1. **东财/新浪接口从 GitHub runner 访问**：首次手动 trigger 需实测；脚本已走项目统一的 UA/Referer（`data/http_client.py`）
2. **GitHub Actions 定时可能延迟**：cron 是「期望时刻」而非保证时刻，实际派发可能迟到数十分钟，详见下方「五、排程延迟与状态提示」
3. **飞书 webhook 限额**：text 单条 6000 字符、机器人每分钟 100 条——摘要远低于上限，无风险
4. **密钥上云**：GitHub Secrets 加密存储，仅 workflow 运行时注入，不会写入日志

## 五、排程延迟与状态提示（v0.21.7）

### 1. GitHub Actions schedule 会迟到，这是平台机制

GitHub Actions 的 `schedule` 事件基于 cron 的 UTC 时刻**排队派发**，而非精确到分钟触发。实测表现（2026-08-17）：

- 复盘排程北京时间 18:00 该跑，实际 `run_started_at` 为 **18:35**（晚 35 分钟）
- 隔夜预案排程北京时间 08:30 该跑，当天整点到 08:42 仍未派发（连 run 记录都没有），属同一排队问题
- 极端情况下（GitHub 队列高负载）排程可能**整体漏跑一次**——这不是代码 bug，也不会自动补跑

因此**不要以「整点几分钟内没收到」判断推送坏了**。核实方式（任一）：

- 网页：仓库 **Actions** 页看对应 workflow 最新 run 的触发时间与结论
- 命令行：`gh run list --workflow push-plan-report -L 5`
- 接口（无需登录）：`https://api.github.com/repos/mowanyy/a-share-daily-review/actions/runs?per_page=10`

超时后仍无 run、或 run 失败需要立刻补一次时，手动触发：

```bash
# Actions 页：左侧选对应 workflow → Run workflow（用默认分支 main）
# 或本地直推（不走 GitHub，需 .env 配好飞书 webhook）：
"E:/conda_envs/envs/mowan_dm/python.exe" -m daily_review push --type plan --date 20260818
```

### 2. 失败/跳过也会收到飞书状态提示（不再无声）

此前只有推送成功才发消息：失败/跳过时飞书端完全无声（`skipped` 在 Actions 里还是绿色对勾），
加上 Actions 页面在公司网络常打不开，等于只能干等。**v0.21.7 起**每个非成功结果都会补发一条短消息：

| 收到内容 | 含义 |
|---|---|
| `【每日复盘】⏭ 隔夜预案 · 日期` + 原因 | 正常跳过：周末休市 / 交易日无数据（法定节假日等），**无需处理** |
| `【每日复盘】❌ 复盘报告 · 日期` + 原因 | 生成失败（采集/LLM/网络等）或主推送失败，需要去查 |

状态提示本身发送失败时不会重复报错，只在本地日志/返回值里加「（状态提示发送失败：…）」注明。
