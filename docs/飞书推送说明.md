# 飞书定时推送说明（v0.22）

用 **GitHub Actions（免费云端定时）+ 本机 Windows 计划任务（秒级准点）+ 飞书群机器人** 实现每日三份报告自动推送。

## 一、推送时间表

| 报告 | 北京时间 | 推送途径 | 触发 | 说明 |
|---|---|---|---|---|
| 复盘报告（盘后） | 18:00 | GitHub Actions | cron `0 10 * * 1-5`（UTC 10:00） | 晚间内容不赶时点，云端关机也能收到 |
| 隔夜预案（盘前） | 07:30 | GitHub Actions | cron `30 23 * * 0-4`（UTC 前一日 23:30） | **提早触发**对冲 GitHub 排程延迟，保证 9:00 预案窗口前到 |
| 开盘策略（竞价后） | 09:25 | **本机计划任务** | schtasks `DailyReview-开盘策略` | 竞价后即时内容，秒级准点，仅周一~周五触发（v0.22） |

- 云端 cron：`0-4` = UTC 周日~周四 ⇒ 北京时间周一~周五早 7:30（避开周六跨日）；`1-5` 同理为周一~周五
- A 股法定节假日（落在周一~周五时）由程序「数据为空则跳过」兜底：工作日休市会推一条 ⏭ 提示，**双休日完全静默不打扰**

## 二、一次性配置步骤

### 1. 飞书群里添加机器人

1. 打开飞书，进入（或新建）一个群
2. 群设置 → 群机器人 → 添加机器人 → **自定义机器人**
3. 给机器人起名（如「每日复盘」）
4. 复制 **Webhook 地址**（形如 `https://open.feishu.cn/open-apis/bot/v2/hook/xxxx`）
5. （可选）设置「签名校验」，会得到一个密钥字符串——填进下方 `FEISHU_SECRET`

### 2. GitHub 配置 Secrets

打开仓库 `https://github.com/mowanyy/a-share-daily-review` →

**Settings → Secrets and variables → Actions → New repository secret**，依次添加：

| Secret 名 | 值 |
|---|---|
| `DEEPSEEK_FALLBACK_API_KEY` | 官方 DeepSeek 的 API key（v0.35.3 起三个 push workflow 都借用它作主 key） |
| `FEISHU_WEBHOOK_URL` | 飞书机器人 Webhook 地址（`https://open.feishu.cn/open-apis/bot/v2/hook/xxxx`） |
| `FEISHU_SECRET` | 飞书机器人的**签名校验密钥**（机器人设了「签名校验」时必填，否则留空） |

> LLM 的非机密配置（`LLM_BASE_URL` / `LLM_MODEL`）已写死在 workflow 里：v0.35.3 起只用官方 DeepSeek（`https://api.deepseek.com` / `deepseek-chat`），workflow env 里 `DEEPSEEK_API_KEY: ${{ secrets.DEEPSEEK_FALLBACK_API_KEY }}` 借用官方 key；旧 secret `DEEPSEEK_API_KEY`（商汤）已被停用，可留作废弃或直接删。

### 3. 验证推送

1. 代码推送到 GitHub 后，打开仓库 **Actions** 页
2. 左侧选「push-review-report」→ **Run workflow** → 手动触发一次
3. 几秒后飞书群里应收到复盘报告推送
4. 三个 workflow 各手动触发一次验证

## 三、本地手动调试

无需 GitHub，本地直接跑（需先 `pip install` 依赖、`.env` 配好 `FEISHU_WEBHOOK_URL`）：

```bash
"E:/conda_envs/envs/mowan_dm/python.exe" -m daily_review push --type review
"E:/conda_envs/envs/mowan_dm/python.exe" -m daily_review push --type plan --date 20260817
"E:/conda_envs/envs/mowan_dm/python.exe" -m daily_review push --type open --date 20260817
```

推送内容为「标题 + 摘要」（约 500-800 字），完整报告仍落盘 `output/` 供回看。

## 四、本地准点推送（Windows 计划任务，09:25 开盘策略）

GitHub Actions 的 `schedule` 排程会迟到（见「六、排程延迟与状态提示」），
对**竞价后即时**的开盘策略不可接受，v0.22 起改由本机计划任务秒级准点触发：

```bash
# 安装（创建计划任务 DailyReview-开盘策略，周一~周五 09:25 触发）
"E:/conda_envs/envs/mowan_dm/python.exe" -m daily_review schedule install
# 只打印将执行的 schtasks 命令，不创建
"E:/conda_envs/envs/mowan_dm/python.exe" -m daily_review schedule install --dry-run
# 查看注册状态 / 卸载
"E:/conda_envs/envs/mowan_dm/python.exe" -m daily_review schedule list
"E:/conda_envs/envs/mowan_dm/python.exe" -m daily_review schedule remove
```

- 任务用 `/SC WEEKLY /D MON,TUE,WED,THU,FRI /ST 09:25` 创建：**仅工作日触发**，双休日连进程都不会启动
- 实际执行 `tools/scheduled_push.bat open`（cd 项目根 + PYTHONPATH + `push --type open`），日志追加到 `output/scheduled_push_open.log`
- 前提：**本机开机**且能访问飞书（公司工位即可）；周末/休市由程序内兜底跳过，不打扰
- 想改时间/重装：直接重跑 `schedule install`（`/F` 覆盖重建）

## 五、已知限制

1. **东财/新浪接口从 GitHub runner 访问**：首次手动 trigger 需实测；脚本已走项目统一的 UA/Referer（`data/http_client.py`）
2. **GitHub Actions 定时可能延迟**：cron 是「期望时刻」而非保证时刻，实际派发可能迟到数十分钟，详见下方「六、排程延迟与状态提示」
3. **飞书 webhook 限额**：text 单条 6000 字符、机器人每分钟 100 条——摘要远低于上限，无风险
4. **密钥上云**：GitHub Secrets 加密存储，仅 workflow 运行时注入，不会写入日志

## 六、排程延迟与状态提示（v0.21.7 / v0.22）

### 1. GitHub Actions schedule 会迟到，这是平台机制

GitHub Actions 的 `schedule` 事件基于 cron 的 UTC 时刻**排队派发**，而非精确到分钟触发。实测表现（2026-08-17）：

- 复盘排程北京时间 18:00 该跑，实际 `run_started_at` 为 **18:35**（晚 35 分钟）
- 隔夜预案排程北京时间 08:30 该跑，当天整点到 08:42 仍未派发（连 run 记录都没有），属同一排队问题
- 极端情况下（GitHub 队列高负载）排程可能**整体漏跑一次**——这不是代码 bug，也不会自动补跑

**v0.22 的应对**：即时内容不再依赖 GitHub——开盘策略改由本机计划任务秒级准点（见「四」）；隔夜预案云端 cron 提早到北京时间 07:30 对冲延迟。云端仅剩不赶时点的复盘 18:00。

因此**不要以「整点几分钟内没收到」判断推送坏了**。核实方式（任一）：

- 网页：仓库 **Actions** 页看对应 workflow 最新 run 的触发时间与结论
- 命令行：`gh run list --workflow push-plan-report -L 5`
- 接口（无需登录）：`https://api.github.com/repos/mowanyy/a-share-daily-review/actions/runs?per_page=10`

超时后仍无 run、或 run 失败需要立刻补一次时，手动触发：

```bash
# Actions 页：左侧选对应 workflow → Run workflow（用默认分支 main）
# 或本地直推（不走 GitHub，需 .env 配好飞书 webhook）：
"E:/conda_envs/envs/mowan_dm/python.exe" -m daily_review push --type plan --date 20260818
```

### 2. 失败/跳过也会收到飞书状态提示

此前只有推送成功才发消息：失败/跳过时飞书端完全无声（`skipped` 在 Actions 里还是绿色对勾），
加上 Actions 页面在公司网络常打不开，等于只能干等。**v0.21.7 起**非成功结果会补发一条短消息；
**v0.22 起双休日完全静默**（周末不推任何消息，零打扰）：

| 收到内容 | 含义 |
|---|---|
| `【每日复盘】⏭ 隔夜预案 · 日期` + 原因 | 工作日休市/交易日无数据（法定节假日等）跳过，**无需处理**；周末不会收到此条 |
| `【每日复盘】❌ 复盘报告 · 日期` + 原因 | 生成失败（采集/LLM/网络等）或主推送失败，需要去查 |

状态提示本身发送失败时不会重复报错，只在本地日志/返回值里加「（状态提示发送失败：…）」注明。
