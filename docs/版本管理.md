# 版本管理约定（Git 工作流）

> 目的：**每轮对话结束自动提交 + 标注版本 + 上传**，保证工程可回溯、可复现。
> 版本号由 AI 根据**工作量和改动大小**标注（用户已授权）。
> 当前：本地仓库（`git init -b main`），远程地址提供后执行 push。

---

## 1. 版本号规则（语义化版本 MAJOR.MINOR.PATCH）

项目处于 `0.x` 开发期。版本推进规则：

| 改动类型 | 例子 | 版本推进 |
|---|---|---|
| **PATCH（小改）** | 修 bug、补文档、环境同步、测试调整、格式化 | `0.2.0 → 0.2.1` |
| **MINOR（新功能）** | 新增涨停池/炸板池爬虫、指标计算、LLM 报告、问答模式 | `0.2.x → 0.3.0` |
| **MAJOR（架构级）** | 架构重构、或正式发布 | `0.x → 1.0.0` |

- 提交时同步更新 `pyproject.toml` 的 `version` 字段，二者保持一致
- 历史版本：
  - `v0.1.0` — 需求分析 + Prompt 工程骨架（文档阶段，未单独提交）
  - `v0.2.0` — 数据采集层起步（东财 K 线 + 新浪实时行情）+ 环境同步（首次入库）
  - `v0.3.0` — 端到端复盘：东财池子/资金流/板块采集 → 连板梯队/题材/炸板指标 → DeepSeek 报告
  - `v0.4.0` — 龙虎榜游资分析（东财龙虎榜 + 买卖席位 + 知名游资识别）
  - `v0.5.0` — 情绪温度（五维加权 + 情绪周期阶段），报告七章
  - `v0.6.0` — 数据看板（近 10 日趋势图表单文件 HTML + LLM 多日解读）
  - `v0.7.0` — 交互问答：RAG 短线知识库（混合检索 + 持续更新）+ 数据工具 function-calling

## 2. 提交流程（每轮对话结束时执行）

```bash
# 1. 提交前检查
git status --short          # 确认改动范围、确认无 data/*.csv 入库
python -m pytest            # 测试通过再提交

# 2. 暂存与提交
git add -A
git commit -m "<type>(<scope>): <简述>"

# 3. 标注版本（按第 1 节规则）
git tag v0.x.y

# 4. 上传（远程配置后）
git push origin main --tags
```

## 3. Commit 消息格式

```
<type>(<scope>): <简述>

示例：
  feat(data): 实现东财涨停池接口
  docs(env): 同步开发环境文档
  fix(cli): 修复控制台中文编码
  chore: 初始化 git 仓库
```

| type | 含义 |
|---|---|
| `feat` | 新功能 |
| `fix` | 修复 |
| `docs` | 文档 |
| `refactor` | 重构（不改行为） |
| `test` | 测试 |
| `chore` | 构建/杂项/初始化 |

| scope（常用） | 含义 |
|---|---|
| `data` | 数据采集层 |
| `prompts` | Prompt 工程 |
| `docs` | 文档 |
| `cli` | 命令行 |
| `env` | 环境/依赖 |
| `(空)` | 全局性改动 |

## 4. 入库 / 不入库

- **入库**：`docs/` `prompts/` `src/` `tests/` `knowledge/` `requirements*.txt` `pyproject.toml` `.gitignore` `.gitattributes` `CLAUDE.md` `README.md`
- **不入库**（`.gitignore`）：`data/*/` `output/*/` `*.csv` `models/` `.kb_cache/` 缓存与虚拟环境目录
