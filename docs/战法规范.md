# 战法规范 — 个人战法编写规范（预留）

> 目的：把用户的**个人交易战法**结构化定义，供 `prompts/modules/次日预案.md` 引用，让 AI 依据战法生成次日预案。
> 状态：**下期启用**。用户提供战法后，按此规范落盘到 `prompts/strategies/`。
> 模板见 `prompts/strategies/战法模板.md`。

---

## 1. 战法是什么

一个战法 = 一套可执行的交易规则，覆盖「什么时候关注、关注什么、怎么买、怎么卖、多大仓位、什么情绪下做」。它描述的是**市场规律 + 个人偏好**的固定化。

## 2. 战法文件规范

- 存放：`prompts/strategies/`，命名 `战法-<名称>.md`
- 文件头用 YAML front-matter 声明元信息（字段见下）
- 正文按 `战法模板.md` 的结构填充

### front-matter 字段
```yaml
---
id: strategy.<slug>       # 如 strategy.longban-relay
name: <战法名称>
version: 0.1.0
status: draft             # draft | active
author: <用户>
applies_to: <适用情绪阶段，如 "修复期/高潮期">
---
```

## 3. 战法必须回答的问题（模板结构）

| 章节 | 必须覆盖 |
|---|---|
| 概述 | 一句话：赚什么钱、核心逻辑 |
| 适用情绪阶段 | 只在冰点/修复/高潮/退潮的哪几个阶段做 |
| 选股/触发条件 | 满足哪些条件才进入观察（板块、身位、封板质量…） |
| 买入规则 | 什么价位/时点/信号买入 |
| 卖出与止损 | 什么信号卖出、止损线、断板处理 |
| 仓位管理 | 单票仓位上限、总仓位、分仓规则 |
| 规避与风险 | 明确**不做**什么（反例更重要） |
| 复盘记录 | 每次执行后记录模板（可用 `examples/` 参考） |

## 4. 编写原则

1. **规则要可判定**：用明确条件，不用模糊描述（"强势股"→"早盘 30 分钟内封板且封单>1亿"）
2. **反例写清楚**：什么情况**不做**，AI 执行预案时更安全
3. **与术语表一致**：晋级/炸板/空间板等用 `prompts/glossary/术语表.md` 定义
4. **一个战法一个文件**：不要混写，便于 AI 按需加载

## 5. AI 如何使用战法

1. `module.plan` 加载当日复盘结构化结果 + 用户指定战法
2. 按战法的触发条件扫描次日可关注对象
3. 输出：关注方向 / 梯队预案（晋级/断板两种情形）/ 买点卖点提示 / 风险警示
4. 若数据不足以判定某条件，**明说缺什么数据**，不强行下结论
