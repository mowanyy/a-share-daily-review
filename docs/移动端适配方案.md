# 移动端适配方案 — Web 工作台响应式设计

> 版本：v0.1.1 · 2026-08-13 · 状态：draft（v0.15.1 起不包含网络分享，仅保留移动端适配）

---

## 1. 设计原则

### 1.1 渐进增强（Progressive Enhancement）

- **桌面端优先**：现有布局（1080px 最大宽度、双列/多列表格）保持不变
- **移动端降级**：通过 CSS 媒体查询在小屏上调整排版、字号、间距
- **不改变功能**：所有按钮、表单、链接在移动端保持可用，只是视觉上重新排列

### 1.2 触控友好

- 可点击元素（按钮、链接、表单控件）最小触摸目标 44×44px（Apple HIG / Material Design 标准）
- 表单输入框在小屏上不缩放、不挤压，保持可读性
- 避免悬停（`:hover`）依赖的操作（移动端无悬停状态）

### 1.3 内容优先

- 看板图表（SVG）自适应缩放，保持数据可读
- 表格在窄屏上提供横向滚动，不裁剪、不换行破坏表格结构
- 导航栏在窄屏上堆叠显示，不隐藏、不依赖汉堡菜单（保持简单，6 个链接堆叠后仍可单手操作）

---

## 2. 断点体系

| 断点 | 目标设备 | 布局策略 |
|---|---|---|
| `≥1080px` | 桌面宽屏 | 现有布局（最大宽度 1080px，居中） |
| `768px–1079px` | 平板/小桌面 | 内边距缩窄，导航栏间隙收小 |
| `≤767px` | 手机竖屏 | 单列布局，字号缩小，按钮全宽，表格滚动 |

---

## 3. 组件级行为规范

### 3.1 导航栏（`nav.top`）

| 属性 | 桌面（≥768px） | 手机（≤767px） |
|---|---|---|
| 布局 | `flex` 水平排列 | `flex-wrap` 折行，两行或三行 |
| 链接字号 | 14px | 13px |
| 链接内边距 | `6px 12px` | `5px 8px` |
| 品牌字号 | 16px | 14px |
| 整体内边距 | `10px 18px` | `8px 12px` |

**规则**：不引入汉堡菜单，不隐藏链接。6 个链接堆叠后约 2-3 行，单手可触。

### 3.2 主内容区（`main`）

| 属性 | 桌面（≥768px） | 手机（≤767px） |
|---|---|---|
| 最大宽度 | 1080px | 100% |
| 左右内边距 | 18px | 12px |
| 上下内边距 | 20px | 12px |
| h1 字号 | 22px | 18px |
| h2 字号 | 17px | 15px |
| 正文/按钮字号 | 14px | 13px |

### 3.3 表单行（`.row`）

| 属性 | 桌面（≥768px） | 手机（≤767px） |
|---|---|---|
| 布局 | `flex` 水平排列 | 堆叠（每个子元素 `width: 100%`） |
| 子元素最小宽度 | `140px` | 无限制 |
| 间距 | 10px | 6px |

**规则**：`@media (max-width: 767px) { .row { flex-direction: column; } .row > div { min-width: 0; width: 100%; } }`

### 3.4 按钮

| 属性 | 桌面 | 手机 |
|---|---|---|
| 内边距 | `7px 14px` | `10px 16px`（增大触摸区域） |
| 字号 | 14px | 14px（不变，保持可读性） |
| 全宽按钮 | 仅特殊场景 | 操作按钮行在手机上全宽竖排 |

### 3.5 面板（`.panel`）

| 属性 | 桌面 | 手机 |
|---|---|---|
| 内边距 | `16px 18px` | `12px` |
| 圆角 | 10px | 8px |

### 3.6 表格

| 属性 | 桌面 | 手机 |
|---|---|---|
| 字号 | 14px | 12px |
| 单元格内边距 | `8px 10px` | `5px 6px` |
| 溢出处理 | 某些表格 `overflow-x: auto` | 所有表格 `overflow-x: auto` |

**规则**：所有 `table` 的外层容器（`<div class="table-wrap">`）加 `overflow-x: auto; -webkit-overflow-scrolling: touch;`。手机端表格可左右滑动查看。

## 4. CSS 实现模式

### 4.1 基础媒体查询

```css
/* 平板及以下 */
@media (max-width: 1079px) {
  main { padding: 16px 14px 48px; }
}

/* 手机 */
@media (max-width: 767px) {
  /* 导航栏 */
  nav.top { padding: 8px 12px; gap: 2px; }
  nav.top a { padding: 5px 8px; font-size: 13px; }
  nav.top .brand { font-size: 14px; margin-right: 8px; }

  /* 主内容 */
  main { padding: 12px; }
  h1 { font-size: 18px; }
  h2 { font-size: 15px; }

  /* 表单行堆叠 */
  .row { flex-direction: column; gap: 6px; }
  .row > div { min-width: 0; width: 100%; }

  /* 按钮触控优化 */
  .btn { padding: 10px 16px; }

  /* 面板内边距缩窄 */
  .panel { padding: 12px; }

  /* 表格紧凑 */
  table { font-size: 12px; }
  th, td { padding: 5px 6px; }

  /* 表格容器溢出滚动 */
  .table-wrap { overflow-x: auto; -webkit-overflow-scrolling: touch; }
}
```

### 4.2 表格溢出容器

每个 `<table>` 外层包裹 `<div class="table-wrap">`，确保在所有屏幕上都可横向滚动。

```html
<div class="table-wrap">
  <table>...</table>
</div>
```

### 4.3 看板内联样式

看板由 `dashboard.py` 生成自包含 HTML（`_HTML_TEMPLATE`），需在模板内补充媒体查询：

```css
@media (max-width: 767px) {
  .board { padding: 12px 10px 32px; }
  .board-head h1 { font-size: 18px; }
  .kpi-grid { grid-template-columns: repeat(auto-fit, minmax(120px, 1fr)); gap: 8px; }
  .kpi { padding: 10px 12px; }
  .kpi .value { font-size: 24px; }
  .panel { padding: 10px 12px; }
  table { font-size: 11px; }
  th, td { padding: 4px 5px; }
  #trend-summary { overflow-x: auto; }
  #emotion-comp { overflow-x: auto; }
}
```

## 5. 看板图表（SVG）适配

### 5.1 现有机制

- 所有图表使用 `viewBox="0 0 900 300"` + CSS `width:100%; height:auto;`
- 已有 `@media (max-width: 900px) { .charts { grid-template-columns: 1fr; } }`

### 5.2 移动端适配要点

| 项目 | 现状 | 移动端调整 |
|---|---|---|
| SVG 缩放 | `width:100%` 自动缩放 | 保持不变 |
| 坐标轴标签 | 11px 固定字号 | 缩小到 10px（内联 SVG 无法响应媒体查询，需在 JS 生成时判断宽度） |
| 图表内边距 | `PAD = { l: 46, r: 16, t: 14, b: 30 }` | 左内边距 46px 在窄屏上过宽，可缩小到 36px |
| 图例 | 12px 字号 | 缩小到 11px |

**规则**：SVG 内文字大小不由 CSS 媒体查询控制（内联 SVG 文本节点不响应外部 CSS 字号变化）。如果窄屏上文字明显过大，可在 `makeScale()` 函数中判断 `window.innerWidth` 动态调整 `PAD` 和字号。

## 9. 注意事项

### 9.1 不做

- ❌ 不引入前端框架（Bootstrap / Tailwind CSS）
- ❌ 不引入 JavaScript 框架（Vue / React）
- ❌ 不做 PWA / Service Worker
- ❌ 不改变现有后端 API
- ❌ 不添加登录/认证

### 9.2 保持

- ✅ 零 CDN 依赖（所有 CSS 内联）
- ✅ 暗色主题（GitHub Dark 风格）
- ✅ 自包含看板 HTML（`dashboard.py` 输出）

### 9.3 已知限制

- 复盘报告（`review.html` 的报告内容）由 LLM 生成 Markdown 转 HTML，表格结构不可控。手机端打开时，LLM 生成的大表格可能超出屏幕，依赖 `overflow-x: auto` 兜底
- 看板 SVG 图表内文字在极小屏幕（<360px）上可能偏小，属于内容量大的正常折衷
