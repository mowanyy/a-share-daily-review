## 一、现状与痛点

### 1.1 当前形态

| 项 | 现状 |
|---|---|
| 产物 | 单文件自包含 HTML `output/{date}_看板.html`（零外链/零 CDN，纯内联 CSS + JS + SVG） |
| 数据链路 | `collect_dashboard`（轻量：只拉 N 日涨停/炸板/跌停池 + hist_days）→ `compute_dashboard`（只算情绪温度 + KPI 标量）→ `build_trend` → `_assemble_payload` → `render_html` |
| Web 集成 | `/dashboard` 页面 = 日期输入 + 天数输入 + iframe（src 指向 `/api/dashboard/view`，**返回 HTML 文本**）；进程内 `DashboardCache`（key=`(date, days)`）+ 磁盘文件复用 + per-key 单飞锁 |
| 内容 | 6 张 KPI 卡 + 2×2 SVG 趋势图（情绪温度 / 涨停连板炸板 / 空间板高度 / 炸板率）+ 趋势摘要表 + 情绪成分拆解表 |
| 交互 | 仅 Web 端改日期 / 改天数（400ms 防抖重载 iframe）；iframe 内**完全静态**，无点击、排序、筛选、下钻 |
| LLM | 无（v0.36 起看板无 AI 文案，`module.dashboard` prompt 已标 deprecated） |

### 1.2 用户反馈痛点

1. **内容不够全面**：只有聚合指标，看不到「是谁在涨」——没有连板梯队、题材板块、涨停个股明细、炸板资金流、龙虎榜。
2. **可交互性不够**：全部静态展示，无法排序、搜索、筛选、点击下钻，改日期才能看到不同日。
3. 美化程度尚可（保持现有深/浅双主题设计 token 与布局风格）。

### 1.3 关键结论：底层数据已齐，缺的是「组装与展示」

`data/{日期}/` 目录已落盘全部明细数据（全量 `collect` 复盘时写入），`analysis/` 已有现成计算函数，**不需要新增任何采集**：

| 数据 | 文件 | 关键字段 |
|---|---|---|
| 涨停池 | `data/{date}/zt_pool.csv` | `code, name, lb_num, first_limit_time, last_limit_time, open_times, seal_amount, turnover, amount, industry` |
| 炸板池 | `data/{date}/zb_pool.csv` | `code, name, break_times, first_seal_time, up_pct, industry` |
| 炸板资金流 | `data/{date}/moneyflow_zb.csv` | `code, name, main_net_inflow, super_net_inflow, big_net_inflow` |
| 龙虎榜 | `data/{date}/lhb_daily.csv` + `lhb_seats.csv` | 21 + 11 列（净买额/席位/游资） |
| 行业映射 | `data/local_cache.py` 的 `industry_map.csv`（7 天 TTL） | code→行业（zt_pool 自带 `industry` 列可兜底） |

可复用分析函数：`compute_ladder`（梯队表/promotion/height_position）、`build_themes`（题材分组/阶段/领涨股）、`analyze_break`（炸板+资金流）、`analyze_lhb`（净买榜/游资聚合）。

## 二、目标与设计原则

1. **内容全面**：看板从「聚合指标」升级为「市场结构 + 个股明细」两级，默认先看结构，深挖看明细。
2. **可交互**：排序、搜索、筛选、跨面板联动下钻、图表悬浮提示，全部纯前端实现。
3. **保持单文件自包含**：`output/{date}_看板.html` 可独立打开、可转发分享、离线可用；零外链断言不破坏。
4. **读盘优先、零新增网络**：明细全部从已落盘 CSV 读（`repo.load_csv`），行业映射走缓存；仅全缺才走现有联网补采路径。
5. **兼容演进**：现有 KPI/趋势区/情绪成分布局不动；`compute_dashboard` 返回结构**只增不删**，现有测试与 Web 缓存链不被破坏。
6. **数据缺失纪律**：各面板独立兜底标注「数据缺失」，绝不编造（沿用 v0.24 起的可用性标注纪律）。

## 三、内容设计（一期）

├─────────────────────────────────────────────────┤

### 3.1 KPI 卡片扩充（总览 Tab）

现有 6 张保留：情绪温度（含阶段 chip）、涨停家数、连板家数、空间板高度（含个股名）、炸板率、跌停家数。

新增 6 张候选（数据均已具备，全部可算）：

| 新增 KPI | 数据来源 | 口径 |
|---|---|---|
| 首板家数 | `compute_ladder` 的 `first_board_count` | 今日 1 板个股数 |
| 晋级率 | `prev_zt` ∩ 今日连板 | 昨日涨停股中今日晋级连板的比例（`promotion` 汇总口径见 §5.2） |
| 最高板位置 | `compute_ladder` 的 `height_position` | 当前高度在近 N 日序列中的分位（label/percentile） |
| 炸板净流出 | `moneyflow_zb.main_net_inflow` 汇总 | 炸板股主力净流入合计（负=流出），缺失时隐藏该卡 |
| 龙虎榜净买 | `analyze_lhb.overview` | 当日龙虎榜净买额合计，缺失/无上榜时隐藏 |
| 涨停总成交额 | `zt_pool.amount` 汇总 | 涨停股成交额合计（亿元） |

- 桌面 3 列网格（12 张 = 4 行），移动端 2 列。
- 「炸板净流出 / 龙虎榜净买」依赖当日是否有数据：`moneyflow`/`lhb` 缺失 → 卡片不渲染（避免「数据不足」刷屏，与 v0.31 的缺失省略纪律一致）；有数据但为 0 → 正常显示 0。

### 3.4 涨停个股明细表（涨停明细 Tab）

| 列 | 字段 | 说明 |
|---|---|---|
| 代码 | `code` | 可搜索 |

### 3.5 数据缺失纪律（各面板独立兜底）

| 场景 | 表现 |
|---|---|

| `lhb_*` 缺失 | 龙虎榜净买 KPI 隐藏 |
| 跌停池恒空（当前数据现状） | 沿用现有 missing 标记，不新增误报 |

## 四、交互设计（一期，纯内联 JS）

全部交互在单文件内实现，遵守零外链约束（沿用 `NS = "http:" + "//..."` 拼接模式，模板不出现协议前缀字面量）。

### 4.1 Tab 导航

- 顶部 Tab 条：「总览 / 市场结构 / 涨停明细」，点击切换面板区，当前 Tab 高亮。
- 切换后调用高度重算：**iframe 高度自适应**（同源 iframe 内 `window.parent` 可调 `fitFrame`，或父页监听 `resize` 重测——实施时采用父页定时/事件重测，避免子页依赖父页函数名）。
- 记忆上次 Tab（`sessionStorage`，刷新不丢）。

### 4.2 表格排序

- 点击表头（`.sortable`）切换 升序 → 降序 → 取消（恢复默认），表头显示 ▲/▼ 指示。
- 数字列按数值比较，时间列（首封 `HH:MM`）按字符串比较，文本列按 localeCompare。
- 排序后联动序号/分页复位。

### 4.3 搜索与筛选（涨停明细 Tab）

- 搜索框：`input` 事件 200ms 防抖，匹配 `code`（前缀/包含）或 `name`（包含），大小写不敏感。
- 行业下拉：选项从当前数据去重生成（含「全部」）；选择后过滤。
- 连板数快速筛选：全部 / 首板（lb_num==1）/ 2 板以上（lb_num>=2）。
- 筛选状态显示在表头下方（「已筛选：行业=小家电，连板≥2 · 清空」），一键清空。

### 4.4 跨面板联动（下钻）

| 触发 | 行为 |
|---|---|
| KPI「涨停家数」卡片 | 跳转「涨停明细」Tab |
| KPI「连板家数」「空间板高度」卡片 | 跳转「市场结构」Tab 并高亮梯队表首行 |
| 梯队表某板数行 | 跳转「涨停明细」Tab + 连板数筛选=该板数 |
| 题材表某行 | 跳转「涨停明细」Tab + 行业筛选=该题材 |
| 涨停明细某行 | 悬浮显示该股完整信息卡（封单/换手/开板次数），点击无动作（一期） |

联动实现：全局 `state` 对象（`{tab, filterLb, filterIndustry, keyword}`），各面板渲染函数统一读 `state`，任何修改 → `reRender()`。

### 4.5 图表 tooltip 增强（总览 Tab）

现状：SVG 圆点只有 `<title>` 原生提示。增强为：

- 鼠标 hover 数据点 → 显示十字准线 + 浮层（日期 + 各序列值），`mousemove` 跟随。
- 图表容器 `position:relative` + 浮层 `position:absolute`，纯 DOM 实现（不引第三方库）。
- 触摸端：tap 数据点显示浮层，点空白关闭。
- 浮层样式复用现有设计 token（`--panel`/`--border`/`--ink-2`）。

### 4.6 移动端（≤767px）

- Tab 条横向可滑动（`overflow-x:auto`），单行。
- 表格沿用 `.table-wrap`/`overflow-x:auto` 横滑容器。
- KPI 网格 2 列；筛选区堆叠。
- 分页控件触控加大。

## 五、数据与技术方案

### 5.1 数据源映射（明细全部读盘，零新增网络）

| 面板 | 读什么 | 方式 |
|---|---|---|
| 连板梯队 | `compute_ladder(zt, zb, prev_zt, height_series)` | zt/zb 走 `_cached`；`prev_zt`/`height_series` 由 `collect_dashboard_detail` 读历史 CSV 重建 |
| 题材板块 | `build_themes(zt, prev_pools, concept_map)` | `concept_map` 走 `data/local_cache.py`（`industry_map.csv`，7 天 TTL）；无缓存时用 `zt_pool.industry` 列兜底 |
| 涨停明细 | `zt_pool.csv` 全字段 | `repo.load_csv("zt_pool", date)` |
| 炸板净流出 KPI | `moneyflow_zb.csv` 汇总 | `repo.load_csv`，缺文件返回 None → 隐藏卡片 |
| 龙虎榜净买 KPI | `analyze_lhb(daily, seats)` | `repo.load_csv`，缺文件返回 None → 隐藏卡片 |

读盘函数均幂等、失败返回空表/None，不抛异常（沿用现有 `_fetch_opt` 成功标志模式）。

### 5.2 计算层扩展（`pipeline.py`）

**原则：现有 `collect_dashboard` / `compute_dashboard` 保持轻量不动**（趋势区与 Web 缓存链依赖它们），新增两个函数：

```python
def collect_dashboard_detail(trade_date: str) -> dict:
    """读盘补明细：prev_zt（前一交易日 zt_pool 读盘）、height_series（hist_days 各日 max_lb 序列重建）、
    moneyflow_zb、lhb_daily、lhb_seats、concept_map（缓存优先）。全部零网络；缺失返回 None/空表 + ok 标志。"""

def compute_dashboard_detail(collected: dict, detail: dict) -> dict:
    """产出：ladder（含 ladder 梯队表 + promotion + first_board_count + height_position）、
    themes（build_themes 列表）、zt_list（涨停明细行）、moneyflow_summary / lhb_summary（或 None）。"""
```

- `height_series` 重建口径：对 `hist_days` 每日本身 zt 池取 `max(lb_num)`，旧→新拼接（与 `compute_ladder` 的 height_position 需要的最新在前方向在组装处消化，沿用 `build_trend` 的「建 dict 按 date 匹配」模式消化方向差）。
- 晋级率 KPI 口径：`promotion` 汇总为**「昨日涨停今日晋级连板占比」** = `today_lianban_count / len(prev_zt)`（`prev_zt` 缺失 → None 隐藏，不显示 0 误导）。
- `generate_dashboard` 主链路改为：`collect_dashboard` + `collect_dashboard_detail` + `compute_dashboard` + `compute_dashboard_detail` → 组装 payload。`routes._generate_dashboard_html` 同步走新链路（惰性 import 同一组函数，改动点单一）。

### 5.3 payload 结构扩展（`dashboard._assemble_payload`）

**只增不删**：

```jsonc
{
  "trade_date": "20260908", "weekday": "周二", "n_days": 10,
  "trend": [ /* 不变 */ ],
  "kpi": { /* 现有键 + 新增 first_board_count / promote_rate / height_position / zt_amount / mf_net / lhb_net（null=隐藏） */ },
  "emotion": { /* 不变 */ },
  "ladder": { "ladder": [{"lb": 1, "count": 42, "leaders": ["000523 红棉股份", "…"], "promote": null}, …],
              "promotion": {"1": 0.19, "2": 0.33, …}, "first_board_count": 42,
              "height_position": {"percentile": 88, "label": "高位" } },
  "themes": [ {"name": "小家电", "member_count": 5, "max_lb": 4, "stage": "发酵", "stage_reason": "…",
               "leader": {"code": "002403", "name": "爱仕达"}, "is_main": true}, … ],
  "zt_list": [ {"code": "002403", "name": "爱仕达", "lb_num": 4, "first_time": "09:25", "open_times": 1,
                 "seal_amount": 0.84, "amount": 5.92, "turnover": 14.69, "industry": "小家电"}, … ],
  "flags": { "prev_zt_ok": true, "moneyflow_ok": true, "lhb_ok": true }
}
```

- `seal_amount`/`amount` 后端转「亿元」数值（前端格式化 2 位小数），减小 payload。
- 无明细数据的日期：`ladder.ladder=[]`、`themes=[]`、`zt_list=[]`，前端渲染「数据缺失」空态。
- `_compact_json` 的 `</` 转义逻辑保持不变（防断 `<script>`）。

### 5.4 单文件自包含约束（不可破坏）

- 新增 JS/CSS 全部内联；不出现 `http://` `https://` `<script src` `<link` 字面量（`NS` 拼接模式）。
- `render_html` 的自包含断言（`tests/test_dashboard.py::TestRenderHtml::test_self_contained_no_external`）必须继续通过 → 新代码不得引入协议前缀。
- Tab/联动用 `sessionStorage`、`document`、`window.parent` 等浏览器内建 API，零依赖。

### 5.5 Web 端集成（一期仅适配，不大改）

## 九、风险与边界

1. **payload 体积**：涨停明细 60–120 行 × 9 字段 → 单文件增长约 30–80 KB，可接受；>200 行走前端分页（每页 50）。
2. **历史日期明细**：梯队/题材/涨停明细只展示**所选日期当日**（按 date 读盘）；历史仅画趋势。明细面板切日期即切换当日数据（现有日期输入天然支持）。
3. **prev_zt 缺失**：梯队晋级率列标「—」，梯队表按当日 `lb_num` 分组照常展示（不依赖 prev_zt）。
4. **题材映射两级降级**：`zt_pool.industry` 列兜底；`industry_map.csv` 缓存命中时增强（concept_map）；两级都无 → 题材面板「数据缺失」。
5. **dt_pool 恒空现状**：跌停相关 KPI/趋势沿用现有 missing 标记，不新增误报；不为此新增采集。
6. **自包含断言**：所有新 JS/CSS 内联、零协议前缀字面量；`NS` 拼接模式是唯一例外写法。
7. **iframe 高度**：Tab 切换后需重测高度，采用父页监听子页高度变化（轮询/`window.parent` 调用 `fitFrame`，同源安全）；移动端横滑容器不依赖高度。
8. **不做**：不新增采集接口；不引入前端框架/图表库/CDN；龙虎榜明细表、炸板资金流明细表、盘中实时刷新不在本期（二期候选）。
